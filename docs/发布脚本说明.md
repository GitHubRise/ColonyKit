## 1. 为什么 dist 里"看不到"脚本

```
sources/ColonyKit/
├─ build.ps1              ← 编译 ColonyKit（不重编内置 RJW，可选部署到 Mods）
├─ build-with-rjw.ps1     ← 编译 ColonyKit + 重编内置 RJW（改 RJW 源码/资源后用）
├─ sync-rjw.ps1           ← 把 sources/rjw/1.6 同步进本工程（守住 packageId 回退）
├─ verify.ps1             ← 静态校验（不启动游戏）
├─ package.ps1            ← 校验 + 编译（连 RJW）+ 打普通 Mod zip
├─ make-portable.ps1      ← 再套一层安装器 + 内置 Harmony
├─ new-mod.ps1            ← 从模板生成新 Mod，**与发布无关**
├─ installer/
│  ├─ install.bat         ← 目标电脑双击入口（纯 ASCII 启动器）
│  ├─ install.ps1         ← 真正安装逻辑
│  └─ 使用说明.txt         ← 随包说明书
└─ dist/                  ← gitignore，只放 zip
```

所以"dist 下面的脚本"实际是**产出 dist 的那套脚本**，它们都在仓库根目录。

## 3. 怎么做的（逐个脚本）

### 3.1 `build.ps1` —— 编译 + 可选部署（正常构建：不重编内置 RJW）

```powershell
.\build.ps1                      # Release 编译，要求 0 error / 0 warning
.\build.ps1 -Clean               # 先删 Source\obj、Source\bin、Source\Rjw\obj|bin；只删 Assemblies\ColonyKit.*，保留 RJW.dll
.\build.ps1 -Deploy              # 编译后 robocopy 到 E:\SteamLibrary\...\RimWorld\Mods\ColonyKit
.\build.ps1 -NoRebuild           # 增量构建（日常用；发布不要用，会漏警告）
```

内置 RJW 由独立工程 `Source\Rjw\RimJobWorld.Main.csproj` 产出 `Assemblies\RJW.dll`。正常构建传 `-p:BuildRjw=false`：
`ColonyKit.csproj` 里那条 `<ProjectReference>` 带 `Condition="'$(BuildRjw)' != 'false'"`，条件不成立就不编 RJW，直接复用上一次的产物。
如果 `Assemblies\RJW.dll` 不存在（全新克隆、或刚 `-Clean` 清过 Assemblies），脚本会直接报错让你先跑 `build-with-rjw.ps1`，不会产出一个缺 RJW 的空壳包。

关键实现：

- **离线工具链**：优先用工作区 `.tools\dotnet\dotnet.exe` + `.tools\nuget`，找不到才退回 PATH 里的 `dotnet`（CI 场景）。
- **`--packages` 必须和上次 restore 一致**，否则 `obj\project.assets.json` 里记录的包路径对不上，build 会重新找包。所以只在 `obj\project.assets.json` 缺失时才 restore。
- **0 警告门槛**：统计日志里 `: error ` / `: warning ` 的条数，任一非 0 就写 `build-error.log` 并抛异常。这是"编译再提交"纪律的执行点。
- **部署前查进程**：`Get-Process RimWorldWin64` 在跑就直接拒绝，否则 Windows 锁 DLL，robocopy 必然失败。
- **robocopy 退出码 0–7 都是成功**（1 = 真的复制了文件，8 以上才是失败），所以脚本末尾 `$global:LASTEXITCODE = 0`，避免调用方误判。
- **`/MIR` 镜像同步**：源里删掉/改名的 Def、Worker 不会在 `Mods\ColonyKit` 留残骸。
- **部署后 SHA256 校验** DLL（`ColonyKit.dll` 与 `RJW.dll` 都校验），确认复制完整。

### 3.1b `build-with-rjw.ps1` —— 连内置 RJW 一起编

```powershell
.\build-with-rjw.ps1
.\build-with-rjw.ps1 -Clean      # 连 Assemblies 整个删掉，RJW 也重编
.\build-with-rjw.ps1 -Deploy
```

- 实现上是 `build.ps1 -WithRjw` 的薄封装，参数完全一致；差别只在传 `-p:BuildRjw=true`，让上面那条 `ProjectReference` 生效，把 `Source\Rjw` 编成 `Assemblies\RJW.dll`。
- 什么时候用：改了 `Source\Rjw` 下的代码、或刚跑过 `sync-rjw.ps1` 同步了 RJW 源码/资源；`package.ps1` 内部也调它，保证发出去的包带最新 RJW。
- 只改 ColonyKit 自己的代码时用 `build.ps1`，省掉 RJW 的编译时间。

### 3.1c `sync-rjw.ps1` —— 内置 RJW 的「进货」脚本

```powershell
.\sync-rjw.ps1 -DryRun           # 只报告将发生的增删改
.\sync-rjw.ps1                   # 实际同步，并重写 docs\内置RJW同步记录.md
.\sync-rjw.ps1 -Force            # 词条文件也整份用源覆盖（会丢 CK_ 词条，慎用）
```

- 源是工作区里的 `sources/rjw/1.6`（可用 `-SourceRepo` 指定别的 RJW 仓库）。
- **镜像**：`Source` → `Source\Rjw`、`Defs` → `Defs\Rjw`、`Patches` → `Patches\Rjw`，源里删掉的文件目标也删；`Source` 会排除 `Analyzers/`、`*.slnx`、`*.sh`、`*.xlsx`、`packages.lock.json` 这类上游工程基建。
- **合并**：`Languages` / `Textures` / `Sounds` 只补新文件，不删本工程自己的资源（`Textures` 里 200 多张 ColonyKit 自有贴图不受影响）。
- **受保护文件**：`RimJobWorld.Main.csproj`、`Harmony\First.cs`、`Harmony\patch_recipes.cs` 永远不覆盖，且复制后校验 `local.colonykit` 回退与 `..\..\Assemblies\` 输出路径还在，校验失败直接中止——这三处丢了不会编译报错，只会在运行时静默退化。
- **差异分类**：内容不同的词条文件默认保留本地版本，分成「本地扩展」（目标比源多出的 CK_ 行，正常）和「上游更新」（源里有、目标没有，需人工合并）两类报告；确认要整份覆盖才加 `-Force`。
- **记录**：成功后写 `docs\内置RJW同步记录.md`（源分支 / commit / 各目录文件数 / 冲突清单），这就是「内置的是 RJW 哪个版本」的唯一答案；接着跑 `build-with-rjw.ps1`。

### 3.2 `verify.ps1` —— 不启动游戏的静态校验

退出码 0 = 通过，1 = 有问题（`package.ps1` 靠退出码拦截）。

检查项：

1. `About/About.xml` 存在；`packageId` 合规（Ludeon 的包名正则）；`supportedVersions` 含 `1.6`。
2. `Defs` / `Patches` 下所有 XML 能解析。
3. 根元素检查：`Defs` 必须是 `<Defs>`，`Patches` 必须是 `<Patch>` 且子节点是 `<Operation>`（还要有 `Class`）。
4. 每条补丁 `<xpath>` 在**本地** Defs 合并文档里试命中：命不中只 **警告**，因为补丁可能改原版/其他 Mod 的 Def。
5. `Assemblies/` 有 `.dll`，且只允许 `.dll` / `.pdb` / `.xml`。

> 注意：`docs/构建与发布.md` 里写的 `tools/check-l10n.ps1`（本地化对账）**目前不存在**，`verify.ps1` 也没有接本地化校验，别照那份文档去找。

### 3.3 `package.ps1` —— 打普通 Mod zip

```powershell
.\package.ps1                    # verify → build → dist\ColonyKit-<modVersion>.zip
.\package.ps1 -SkipBuild         # 已经编译过，只重新打包
.\package.ps1 -SkipVerify        # 跳过静态校验（不建议）
.\package.ps1 -NoRjw             # 不带内置 RJW：dist\ColonyKit-<modVersion>-noRjw.zip
```

流程：

1. 跑 `verify.ps1`，退出码非 0 就中止 → 2. 跑 `build.ps1` → 3. 检查 `Assemblies\ColonyKit.dll` 存在 → 4. 读 `About.xml` 的 `modVersion` 当版本号 → 5. 复制运行期目录到 `%TEMP%\ColonyKit-package-<guid>`：

   `About` `Assemblies` `Defs` `Patches` `Languages` `Translations` `Textures` `Sounds` `Blueprints`

6. 布局断言：`About\About.xml` 必须在第一层；不许出现 `Source/`、`obj/`、`bin/`；`Assemblies/` 只许 `.dll`/`.pdb`。
7. 压缩：**手写 zip entry 名并 `\`→`/`**。`CreateFromDirectory` 在 Windows 上会写 `\`，Linux 工具链和部分解压器会认不出目录。
8. 打完回读 zip，打印文件数与第一层目录，`finally` 里删临时目录。

`-NoRjw` 时流程多两步：构建改走 `build.ps1 -NoRjw`（不重编 RJW，也不要求 `Assemblies\RJW.dll` 已存在），复制完调用 `tools\strip-rjw.ps1` 的 `Remove-RjwContent` 把 RJW 内容从 staging 里摘掉；产物名带 `-noRjw` 后缀。

摘除由**内容**决定，不是删个 DLL 就完事（少一处启动日志就刷红）：

| 摘掉的东西 | 为什么 |
|---|---|
| `Assemblies\RJW.dll`、`RJW.pdb` | 程序集本体 |
| `Defs\Rjw`、`Patches\Rjw` | RJW 的 Def 与补丁 |
| `Defs\Robotics\RJWCompat.xml` | 根元素是 `<rjw.HediffDef_SexPart>`，没 RJW.dll 会报找不到类型 |
| `Defs\Robotics\MkVBody.xml` 的 `MechGenitals` / `MechChest` / `MechAnus` | 三个 BodyPartDef 定义在 RJW 里 |
| `Languages\*\DefInjected` 里的 RJW 内容 | 13 个 `rjw.*` 类型目录整目录删；其余目录里指向 RJW def 的词条逐条删，删空的文件与目录一并清掉；解析不了的文件按正则判断，全是 RJW 条目才删 |
| `Languages\*\Keyed\RJWMainTab.xml`、`Textures` 下的 RJW 图标 | RJW 自带资源，留着只是白占体积 |
| `About.xml` 的 `incompatibleWith` 里的 `rim.job.world` | 不内置了就不该再禁止外部 RJW |

代码侧不用动：`ColonyKit.dll` 不引用 RJW 程序集，`RjwCompat` 用 `Type.GetType("rjw.xxx, RJW")` 探测，RJW 缺席时相关分支自动失效。

### 3.4 `make-portable.ps1` —— 带安装器 + 内置 Harmony 的便携包

```powershell
.\make-portable.ps1
.\make-portable.ps1 -SkipBuild -SkipVerify
.\make-portable.ps1 -NoRjw
.\make-portable.ps1 -HarmonyPath 'D:\SteamLibrary\steamapps\workshop\content\294100\2009463077'
```

流程：

1. 调 `package.ps1` 拿到 `dist\ColonyKit-<version>.zip`。
2. 找本机 Harmony：顺序是 `-HarmonyPath` → `E:`/`D:`/`C:\SteamLibrary\...\workshop\content\294100\2009463077` → `%ProgramFiles(x86)%\Steam\...`。判定条件是三件套齐全：`About\About.xml`、`1.6\Assemblies\0Harmony.dll`、`LICENSE`，且 About 里有 `brrainz.harmony`。找不到就明确报错要求 `-HarmonyPath`。
3. 解压 Mod 包到 `staging\ColonyKit`，整个 Harmony 目录复制成 `staging\Harmony`，再把 `installer\install.bat` / `install.ps1` / `使用说明.txt` 放到第一层。
4. 逐项断言必存在文件（`ColonyKit\About\About.xml`、`ColonyKit.dll`、`Harmony\1.6\Assemblies\0Harmony.dll`、`Harmony\LICENSE`、三个安装器文件）。
5. 同样手写 entry 名压成 `dist\ColonyKit-<version>-portable.zip`，回读校验第一层。

> 注意：**现在只产出 `-portable.zip`**，不会再产出 `-portable-harmony.zip`。`dist` 里那份 `ColonyKit-0.0.2-portable-harmony.zip` 与 `-portable.zip` 文件大小完全相同（8,264,876 字节）、第一层结构相同，是**手工复制改名**的，不是脚本产物，可以删。

### 3.5 `installer/` —— 目标电脑上的安装器

`install.bat`：纯 ASCII 启动器，避免中文 cmd 代码页炸掉。`chcp 65001` → 找同目录 `install.ps1` → `-ExecutionPolicy Bypass` 调 PowerShell，透传参数（`[RimWorld 路径]` / `/auto`）。

`install.ps1`：

1. 定位 RimWorld：命令行参数 → `%RIMWORLD%` → 注册表 Steam 路径 → `libraryfolders.vdf` 里其它库 → C–H 盘常见路径（Steam / SteamLibrary / Program Files / Games / GOG）→ 都没有就提示把文件夹拖进窗口。
2. 检查 `RimWorldWin64` 是否在跑，在跑就拒绝（文件锁）。
3. Harmony：`Mods\Harmony`、创意工坊目录、`Mods` 下任意 About 含 `brrainz.harmony` 都算已装 → 跳过；否则复制随包 `Harmony\` 到 `Mods\Harmony`（已有旧目录则先 `Harmony.bak-1..99`）。
4. 备份旧版：`ColonyKit` → `ColonyKit.bak-N`（找第一个空位，99 个满了报错）。
5. `robocopy /MIR` 复制，退出码 ≥8 才失败；安装后校验 `About.xml` 与 `ColonyKit.dll` 都在。
6. 读 `About.xml` 的 `modVersion` 显示安装版本。
7. 外部 RJW 检查：`Mods\RimJobWorld` 或 `ModsConfig.xml` 里有 `rim.job.world` 就提示——ColonyKit 已内置 RJW 1.6，同时开会重复 Def。
8. 输出绿色成功 / 红色错误 / 黄色警告，`/auto` 时不弹"按回车退出"。

### 3.6 `new-mod.ps1`

从 `mod-template` 复制生成一个新 Mod（改名、改 `packageId` 等），**不参与 ColonyKit 发布**，读代码时不用管。

### 3.7 两个通用坑（改这套脚本必读）

**① `$LASTEXITCODE` 在全新进程里是 `$null`，而 `$null -ne 0` 为真。**

调用方写 `& package.ps1; if ($LASTEXITCODE -ne 0) { throw }` 时，如果 `package.ps1` 一次外部程序都没调（典型的 `-SkipBuild -SkipVerify`），`$LASTEXITCODE` 会保持 `$null` 或调用方上一次原生命令的残留值，于是**明明成功也会误报失败**。2026-10-27 出 0.0.3 时撞上了：`make-portable.ps1 -SkipBuild -SkipVerify` 必挂。

修法（已落地）：出包脚本在调用子脚本前 `$global:LASTEXITCODE = 0`，成功路径结束时再归零（`build.ps1` 早就这么处理 robocopy 的 0–7 成功码了）。

**② `.ps1` 必须是「UTF-8 带 BOM」。**

脚本里有大量中文注释与提示串。Windows PowerShell 5.1 在**没有 BOM** 时按系统 ANSI 代码页（简体中文是 GBK）解析文件，中文变成乱码字节，直接抛 `Unexpected token` 之类的**语法错误**——看起来像乱码，其实是解析失败。`build.ps1` / `verify.ps1` / `package.ps1` / `make-portable.ps1` / `installer/install.ps1` 都带 BOM；用编辑器或脚本批量改完，记得检查首三字节是不是 `EF BB BF`。

```powershell
# 补 BOM：读成文本，再以带 BOM 的 UTF8 写回
$enc  = New-Object System.Text.UTF8Encoding($true)
$text = [System.IO.File]::ReadAllText($path, (New-Object System.Text.UTF8Encoding($false)))
[System.IO.File]::WriteAllText($path, $text, $enc)
```

（`.bat` 反过来：`install.bat` 故意保持纯 ASCII 无 BOM，避免 cmd 把 BOM 当命令。）

## 4. 调用链

```text
.\make-portable.ps1
  └─ package.ps1
       ├─ verify.ps1              → 退出码非 0 中止
       ├─ build-with-rjw.ps1      → build.ps1 -WithRjw → dotnet build -p:BuildRjw=true
       │    └─ ColonyKit.dll + RJW.dll，0 error / 0 warning，否则写 build-error.log
       └─ dist\ColonyKit-<ver>.zip

  ├─ staging: ColonyKit\ + Harmony\ + install.bat + install.ps1 + 使用说明.txt
  └─ dist\ColonyKit-<ver>-portable.zip

.\sync-rjw.ps1            （改了 sources/rjw 之后）
  ├─ 镜像 Source / Defs / Patches，合并 Languages / Textures / Sounds
  ├─ 校验 3 个受保护文件（packageId → local.colonykit 回退）
  ├─ 写 docs\内置RJW同步记录.md
  └─ 下一步：.\build-with-rjw.ps1
```

## 5. 产物命名

| 产物 | 生成者 | 第一层 |
|---|---|---|
| `dist\ColonyKit-<modVersion>.zip` | `package.ps1` | `About` `Assemblies` `Blueprints` `Defs` `Languages` `Patches` `Sounds` `Textures` `Translations` |
| `dist\ColonyKit-<modVersion>-portable.zip` | `make-portable.ps1` | `ColonyKit/` `Harmony/` `install.bat` `install.ps1` `使用说明.txt` |
| `dist\ColonyKit-<modVersion>-noRjw.zip` | `package.ps1 -NoRjw` | 同普通包，内容里没有 RJW |
| `dist\ColonyKit-<modVersion>-portable-noRjw.zip` | `make-portable.ps1 -NoRjw` | 同便携包，`ColonyKit/` 里没有 RJW |
| `*-portable-harmony.zip` | ❌ 无脚本生成 | 手工改名的副本 |

`<modVersion>` 直接读 `About/About.xml` 的 `<modVersion>`，**所以想换版本号只改 About 一处**，zip 名自动跟着变。

## 6. 发布一个版本（以 0.0.3 为例）

```powershell
cd E:\RimWorld-WorkSpace\sources\ColonyKit
```
