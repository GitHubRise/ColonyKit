## 简介

`CK_ConveyorHub` 是一块 **1×1 转向盘**，和 `CK_ConveyorBelt` 共用 `Building_ConveyorBase` 的**自动路由**：不靠玩家设方向，物品会沿相邻履带 BFS 找最近的立体库，再逐格送过去。

## 描述

- 占地 **1×1**，可旋转；`Building_ConveyorTurntable` 当前是空子类，**行为与双向履带完全相同**，转向盘没有独立的“出口方向”逻辑。
- 成本 **30 钢 + 1 零部件**；150 HP / 8 质量 / 500 工作量；`maxItemsInCell=1`；可通行（PassThroughOnly）；可拆除/可最小化搬运（`minifiedDef`）。
- 研究前置：三级立体仓库技术 `CK_StorageTier3`。
- **没有 `designationCategory`**：正常建造菜单里看不到，属于暂停开发；可通过开发者/蓝图/已有存档测试。
- 不耗电，没有 `CompPowerTrader`。
- 自动路由：
  - 每 `MoveIntervalTicks=30` tick 处理一次；
  - 当前格物品先看是否紧邻立体库，是则 `TryStoreInNetwork` 直接入库；
  - 否则在相邻 `Building_ConveyorBase` 网络中 BFS，找到“相邻有立体库”的履带格，向第一步移动；
  - 无路可走时留在原地，不落地、不损坏。
- 只搬 `ThingCategory.Item`，跳过尸体/最小化建筑/堆数为 0 的物品。
- 选中或载货时 `DrawAt` 叠加两枚沿路由方向移动的箭头；空闲未选中不显示。
- 检视字符串显示“自动输送至最近的立体库 (x,z)”或“附近没有可用的立体库”。
- 没有端口/方向切换/自动出库；立体库任意一条边相邻的履带都算连接，不要求正中端口。

## 绘制调用逻辑图

```text
每 30 tick
  └─ Building_ConveyorBase.Tick
        └─ MoveItems
              ├─ 当前格物品（非尸体/非最小化）
              ├─ TryStoreAdjacent：相邻/扩展 1 格内有立体库 → 直接入库
              └─ TryFindNextCell：BFS 相邻履带
                    ├─ 找到最近“贴仓库”的履带格 → 向第一步移动
                    └─ 找不到 → 留在原地

自动路由
  [履带] → [履带] → [转向盘] → [履带] → [立体库]
       每格 30 tick；转向盘和履带没有行为差异
```

## 所含功能

- 1×1 转向节点，自动路由时可拐弯。
- 与双向履带互通、自动送入最近立体库。
- 30 tick/格移动；可最小化搬运。
- 选中/载货时显示方向箭头。

## 如何使用

1. 当前正常建造菜单没有该建筑；测试时用开发者/蓝图或已有存档。
2. 把履带/转向盘铺在立体库任意一条边旁；自动路由会找最近仓库。
3. 不需要旋转或设端口；转向盘和履带可以混铺。
4. 选中任意履带/转向盘看检视字符串，确认目标格。

## 常见问题

**Q：转向盘和双向履带有什么区别？**  
A：当前没有行为区别，都是 `Building_ConveyorBase` 自动路由；转向盘只是另一种外观/成本。

**Q：为什么物品不拐弯？**  
A：自动路由会拐弯；检查是否连续铺了履带、目标仓库是否可达、目标格是否被占。转向盘的 `Rotation` 不影响路由。

**Q：能接出库吗？**  
A：不能；履带只负责入库。取出用检视面板/自动出库 Job。

**Q：为什么建造菜单找不到？**  
A：暂停开发，Def 没有 `designationCategory`；需要开发者/蓝图生成。
