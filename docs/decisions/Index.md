# 决策记录（ADR）

> 目的：记录「为什么这样选」，避免后期只看到结果、不知道约束和备选方案，重复调查。
> 触发：M1-0 / M2-0 / M3-0 / M4-0 / M5-0 / M6-0 等技术选型，以及任何会影响存档、兼容、性能的决定；7000 地下室、8000 空中力量为 G1/G2 构想，尚未排期。

## 模板

新建 `docs/decisions/<topic>.md`，按下面结构写：

```markdown
# <决策标题>

- 状态：提议 / 已接受 / 已废弃
- 日期：YYYY-MM-DD
- 关联任务：M3-0
- 影响范围：模块 / 存档 / 兼容 / 性能

## 背景
要解决什么问题，现状和约束是什么。

## 候选方案
| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|

## 结论
选哪个，为什么；哪些条件变化时需要重新评估。

## 影响
代码落点、存档格式、兼容策略、性能预算、需要补的测试。

## 验证
怎么证明这个决定是对的（原型、压测、兼容冒烟）。
```
