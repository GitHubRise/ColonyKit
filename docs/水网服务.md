## 简介

淋浴和农业都要用水，所以水网下沉到 `Core/Water/`，两个模块只做「消费者」，不各自维护水箱与管道。单位统一用升（`L`），内部 `float`，UI 取整。

这是 ColonyKit 唯一的跨模块共享服务；模块之间不直接引用，需要协作时走它。

## 描述

- `HygienePipeMapComp` 持有本图的 `PlumbingNet` 集合；地图加载后按建筑重建拓扑，建筑增删时增量更新。
- `PlumbingNet` 按管道连通性分组，缓存总容量、存量、产出、消耗、断水原因。
- 实际 Comp（`Source/Modules/Hygiene/Dbh/`）：
  - `CompPipe`：连接件，`mode` 区分 Water / Sewage；
  - `CompWaterPumpingStation`：耗电产水，需同网有水井；
  - `CompWaterStorage`：水箱容量与存量；
  - `CompWaterInlet`：水井地下水容量；
  - `CompWaterHeater`：供电时给同网提供热水；
  - 淋浴等洁具直接调用 `PlumbingNet.PullWater` / `PullHotWater`。
- 结算：`MapComponentTick` 每 tick 汇总一次；产水按 `min(泵容量, 井容量) / 60000` 每 tick 推入水箱；无井则产水为 0。
- 水管像电缆：`isEdifice=false`、`altitudeLayer=Conduits`、`passability=Standable`，可铺在墙下；`drawStyleCategory=Default1D` 提供拖拽布线。
- 铺管可视化：`SectionLayer_WaterPipeOverlay` / `SectionLayer_SewagePipeOverlay` 在选中同模式管道建造设计器时，把已安装管件按 4×4 连接图集画在 `MetaOverlays`；水管蓝色、污水管青绿色。管道靠四邻自动连管，没有朝向，因此水管/污水管以及单张贴图的水箱、水泵等都不提供 Q/E 旋转。
- 存档：只存每个网的存量 + 建筑状态；读档后按建筑重建拓扑，不存图结构。
- 断水：消费者停机、Gizmo/Alert 给出可读原因；恢复供水后自动重启。
- 热水（淋浴用）是水网的一个可选属性：`CompWaterHeater` 给网加热，温度随结算更新；农业不关心温度。

## 绘制调用逻辑图

```text
泵(耗电) ──▶ 管道 ──▶ 水箱(容量) ──▶ 消费者(淋浴/喷灌)
   │            │           │              │
   └─ 产水 L ───┴─ 连通 ────┴─ 存量 L ─────┴─ 需求 L + 优先级

每 250 tick:
  WaterNet.Tick()
    ├─ 汇总 pump.Produce()
    ├─ 汇总 consumer.Demand()
    ├─ 按优先级分配 → 扣 tank.Stored
    └─ consumer.SetRunning(是否满足, 停机原因)

建筑增删 / 读档:
  MapComponent_WaterNetwork.Rebuild()
    └─ 按管道连通性重建 WaterNet → 重新挂接 comps
```

## 所含功能

- 管道连通分组与增量重建；
- 产水/容量/存量/消耗统计；
- 无井不产水、无泵不抽水、无水箱不储水；
- 热水（供淋浴）；
- 存档只存状态，读档重建拓扑；
- 铺管时用覆盖层显示已安装管网（水管蓝色、污水管青绿色），只在选中对应建造设计器时出现；
- 水管可铺墙下、可拖拽布线；
- 供淋浴/洁具使用，农业后续接入。
