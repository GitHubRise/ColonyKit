| 项 | 内容 |
|---|---|
| 源码 | [`sources/devmenu-zh`](../../devmenu-zh/) |
| 关键文件 | `Source/DevMenuZh.cs`、`Translations/DevMenuLabels.xml`、`Languages/ChineseSimplified/DefInjected/MainButtonDef/*.xml` |
| 机制 | Harmony 后缀拦截 `LudeonTK.DebugActionNode.LabelNow`；翻译表外置；设置里切换「极简/常用/全量」方案 |

**0.0.2 已移植的文件**：

| ColonyKit 路径 | 作用 |
|---|---|
| `Translations/DevMenuLabels.xml` | 翻译表（约 72 KB，来自 `sources/devmenu-zh` 当前版本） |
| `Source/Modules/Localization/DevLabelTranslations.cs` | 读表、查词、常量/Def 回落 |
| `Source/Modules/Localization/Patch_DebugMenu.cs` | `DebugActionNode.LabelNow` Postfix + Debug 窗口 tooltip Transpiler |
| `Source/Modules/Localization/LocalizationModule.cs` | 模块入口、冲突检测、`ShouldTranslate` 门控 |
| `Source/Modules/Localization/LocalizationSettings.cs` | 开关 + 翻译方案持久化 |
| `Source/Settings/Pages/GeneralSettingsPage.cs` | 常规设置页：翻译方案入口与开关 |
| `Source/Settings/Pages/Dialog_LocalizationSchemes.cs` | 方案编辑窗口（新建/删除/全选/全不选/恢复默认 + 翻译表状态/重载） |

- 检测到原 `devmenu-zh`（`local.devmenuchinese`）启用时，两个补丁都会运行；本模块仍加载完整翻译表（34 个菜单组），可补上原 Mod 方案未覆盖的底部条目，建议只保留一个以避免文本来源混乱。
- quicktest 自检：翻译表 882/882、tooltip/品质返回中文；未人工打开 Debug 菜单/方案窗口/设置页。

**注意**：这是「开发者菜单」汉化，不是通用本地化框架；如果 `localization` 模块要做全 Mod 文本，需要另建 Keyed/DefInjected，不要把约 880 条调试词条当成游戏内文本。

## 3. 淋浴（Dubs Bad Hygiene）

| 项 | 内容 |
|---|---|
| 源码 | [`sources/dbh/1.6/Source`](../../dbh/1.6/Source/) |
| 关键文件 | `DubsBadHygiene/Building_shower.cs`、`JobDriver_takeShower.cs`、`ShowerCleanup.cs`、`Need_Hygiene.cs`、`Building_AssignableFixture.cs`、`CompWaterConsumer` 相关、`HarmonyPatches_Plumbing.cs` |
| 机制 | 卫生需求 + 淋浴 Job + 给排水管网 + 热水 + 淋浴后清理 RJW 精液/打扫房间 |
| 规模 | DBH 整体约 19k 行；淋浴相关数百行，但强依赖 DBH 的 `PlumbingNet` / `HygienePipeMapComp` / `Need_Hygiene` |
| 移植难度 | 高（不能只抠一个文件） |
| 目标模块 | `hygiene` |
| 建议 | **已迁移（0.0.3）**：卫生需求、洁具、水网、热水、排污、洗涤与农业链全部落地；本轮补上 DBH 音效/特效、风泵/泵站/深水井/巨型水塔/燃气锅炉/消防喷淋/原始水井/低温采水节点、便盆/水壶/冰箱/仿生/粪渣炼油、照护与清洁工作、9 个研究节点。仍未迁：真空马桶、飞船排污口、水回收系统、装饰水景、马赛克地砖、DBH 三种肠道疾病（合并为 `CK_GutBug`）、其它语言翻译 |

**风险**：DBH 是闭源反编译重建工程；直接复制代码要遵守其许可；`ShowerCleanup` 依赖 RJW 的 `FilthCum` 等 Def，需要可选检测。

**0.0.3 已知简化（不是断链，但和 DBH 有差距）**：

- 深水井让整张以它为主要水源的水网不受地表污染；若网上还接了建在水面上的水龙头/取水点（`CompSurfaceWaterInlet`），仍按地表水算。
- 冰箱是自带制冷的 `Building_Storage`：50 W、可开关，通电时格上的食物跳过腐烂 tick；靠 `CompRottable` 前缀补丁实现，不改变房间温度显示。
- 医生洗澡、便盆清洗只做动作和清洁结算，没有扣水；便盆洗完留在水边，需要玩家再搬回卧室。
- 音效 11/12 有触发点，只剩 `CK_VacuumToilet` 留给未迁的真空马桶；4 个 Effecter 全部有触发点，`CK_MoteFecalBit`/`CK_MoteBucket` 随对应 Effecter 使用。


## 4. RJW 本体（RimJobWorld）

| 项 | 内容 |
|---|---|
| 源码 | 原始 [`sources/rjw/1.6/Source`](../../rjw/1.6/Source/)；已复制到 [`Source/Rjw`](../Source/Rjw/) |
| 关键文件 | `Common/RMB/RMB_Invite.cs`、`JobDrivers/JobDriver_Sex*.cs`、`Comps/CompRJW.cs`、`Settings/RJWSettingsController.cs` |
| 最近改动 | 群交邀请（接收方邀请、监狱之间、邀请结果提示）、多伴侣/flirt、多人 JobDriver 调整 |
| 规模 | 386 个 `.cs` / ≈1.6 MB；已整体迁入，不再“只做兼容层” |
| 移植方式 | 独立工程 `Source/Rjw/RimJobWorld.Main.csproj` → `Assemblies/RJW.dll`；ColonyKit 不引用其类型；两个 `Mod` 子类由 RimWorld 分别实例化 |
| 同步 | `.\sync-rjw.ps1`：从 `sources/rjw/1.6` 镜像 `Source`/`Defs`/`Patches`、合并 `Languages`/`Textures`/`Sounds`，保护 3 个本地改动文件并写 `docs/内置RJW同步记录.md`；`-DryRun` 可先看差异 |
| 构建 | `.\build-with-rjw.ps1` 连 RJW 一起编；`.\build.ps1` 只编 ColonyKit、复用现有 `RJW.dll` |
| 资源 | `Defs/Rjw`、`Patches/Rjw`、`Languages/*`、`Textures/*`、`Sounds/*` 合并到 ColonyKit 根目录 |
| 包名 | 迁移后 Mod 的 packageId 是 `local.colonykit`；RJW 内部自引用已改为 `rim.job.world` → `local.colonykit` 回退 |
| 冲突 | 外部 `rim.job.world` 与内置版**不兼容**：同时启用会重复 Def/补丁；`About.xml` 已列入 `incompatibleWith` |

**风险**：RJW 更新频繁；后续同步上游时用 `sync-rjw.ps1`（脚本会保护 `rim.job.world` → `local.colonykit` 的回退，手工整目录覆盖会把它冲掉）。RJW 的 `First` 静态构造会 `PatchAll` 自己的程序集，ColonyKit 的 `Bootstrap` 只补 ColonyKit 程序集，二者不重叠。

## 5. 移植顺序

1. **✅ `localization`**：已移植开发者菜单汉化（外置表 + 方案 + 冲突检测）；quicktest 自检通过，UI 待人工点击。
2. **`storage`**：先 `StackLimitManager`/`StackRules`，再仓库核心/传送带；这一步决定 `storage` 模块的 API。
3. **`hygiene`**：先做 DBH 依赖版 `ShowerCleanup`（最小闭环），再评估是否重写给排水。
4. **✅ `rjw`**：已整体迁入（`Source/Rjw` + 全量运行期资源），作为独立 `RJW.dll` 随 ColonyKit 构建。

## 6. 移植约束

- 不直接修改 `sources/mod-template`、`sources/dbh`、`sources/stackxxl`、`sources/rjw`、`sources/devmenu-zh`；所有改动只进 `sources/ColonyKit`。
- 移植代码统一改命名空间到 `ColonyKit.Modules.<Module>`；Def 的 `defName` 统一 `CK_` 前缀，避免与来源 Mod 冲突。**RJW 例外**：保留 `rjw` 命名空间与原有 Def 名，降低上游同步成本。
- 来源 Mod 作为**可选依赖**时，代码/补丁必须有 `ModsConfig.IsActive` 守卫；作为**复制**时，在 `About.xml` 里不要声明依赖。
- 复制前记录来源 commit（见各仓库 `git log`），并在本文件更新「已移植」状态。
- 贴图/音效等资源复制前确认许可；0.0.2 不复制任何贴图。
