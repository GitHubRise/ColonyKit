## 简介

搬运工把符合过滤条件的物品送到立体库的**入库口**，物品被收进建筑内部，不占地图格；同类物品会合并到已有堆。

## 描述

- 立体库默认是 **Low 优先级缓冲**：普通库存区能放时，原版搬运优先；只有库存区放不下/没有库存区时，`WorkGiver_HaulToWarehouse` 才把货送进立体库。
- 入库直接复用原版 `JobDefOf.HaulToContainer` 的 `JobDriver_HaulToContainer`：取货 → 走到建筑 → 存入内部 `ThingOwner`，不额外写一套搬运路径。
- 过滤/容量/断电在 WorkGiver 接活时检查；`Accepts` 使用 `storeSettings.AllowedToAccept`，所以 Storage 页的过滤会生效。
- 过滤/优先级变更后，已经开始的 Job 可能继续完成，下一次按新设置。
- 与 Stack XXL 同开时，单堆上限变化会影响合并与堆数。

## 绘制调用逻辑图

```text
地上有可搬运物品
   │
   ▼
WorkGiver_HaulToWarehouse.HasJobOnThing
   ├─ 有更高优先级库存区可放 → 让给原版搬运
   └─ 没有库存区/库存区满 → 找立体库
         ├─ 断电/过滤不允许/已满且不能合并 → 跳过
         └─ 可存 → JobDefOf.HaulToContainer
                       │
                       ▼
              JobDriver_HaulToContainer
                       ├─ 取货
                       ├─ 走到立体库
                       └─ 存入 ThingOwner（按堆合并）
                              │
                              ▼
                         库存 ITab 更新
```

## 所含功能

- 搬运工自动入库（库存区满/无库存区时）。
- 复用原版 HaulToContainer 路径与携带量。
- 过滤/容量/断电接活检查。
- 堆合并、件数/堆数。

## 如何使用

**前提**：库已建好、通电、未满；过滤允许该物品；普通库存区放不下。

1. 设置过滤/优先级（2004）。
2. 殖民者自动接活；库存区满时把物品送入立体库。
3. 在 ITab 看库存增加。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 东西一直不搬 | 过滤不允许/优先级低/库满/没电 | 看 2004 与 ITab |
| 搬到门口又放下 | 入库口被占/建筑被禁用 | 清出入口/启用建筑 |
| 堆数对不上 | Stack XXL 改了单堆件数 | 看件数而不是堆数 |
