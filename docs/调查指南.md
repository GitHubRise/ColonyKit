# 调查指南（Investigation）

> 目的：出问题时，用最短路径回答四个问题——**哪个功能、哪条日志、哪个文件、哪个 key**。
> 维护：新增模块 / 日志 tag / `defName` 前缀 / 设置 key 时，同步更新本文的表。

## 1. 五分钟定位流程

1. **复现**：干净存档 + 只开 Core / Harmony / ColonyKit（对应 M8-8）。
2. **抓日志**：打开 `Player.log`，先过滤 `[ColonyKit]`。
3. **定功能**：按日志里的 `[<Module>]` 找到对应模块。
4. **查状态**：对照 [README 任务清单](../README.md#5-任务清单)（M0–M8），确认这个功能是「已实现」还是「规划」。
5. **查决策**：看 [decisions/Index.md](decisions/Index.md)，确认当时的选型和已知限制。
6. **最小化**：关掉其他模块、其他 Mod，二分定位；不要一次改多处。
7. **收尾**：修复后同一次提交里更新任务状态、功能文档的「完成情况」和 README 变更记录。

## 2. 日志

- 统一前缀：`[ColonyKit][<Module>]`；模块 tag 见 §3。
- 日志只走 `ModLog.Message/Warning/Error`，不要直接调 `Verse.Log`。
- 过滤命令：

```powershell
$log = "$env:USERPROFILE\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Player.log"
Select-String -Path $log -Pattern '\[ColonyKit\]' | Select-Object -Last 100
```

- 加载成功基线（M0-7）：`[ColonyKit] loaded; modules=6`。
- 异常优先看 `Exception` / `Could not load` / `Failed to load` 附近，再看本 Mod 的最后一条日志。

## 3. 稳定标识表

| 模块 | 模块 Id | 日志 tag | 关键 `defName` | 设置 / Scribe key 前缀 |
|---|---|---|---|---|
| 内核 | `core` | `[ColonyKit][Core]` | 无 | `ck_core_*` |
| 水网 | `water` | `[ColonyKit][Water]` | `CK_WaterPipe` / `CK_WaterPump` / `CK_WaterTank` | `ck_water_*` |
| 淋浴 | `hygiene` | `[ColonyKit][Hygiene]` | `CK_Shower` / `CK_WaterHeater` | `ck_hygiene_*` |
| 立体库 | `storage` | `[ColonyKit][Storage]` | `CK_VerticalWarehouse` | `ck_storage_*` |
| 农业 | `agriculture` | `[ColonyKit][Agriculture]` | `CK_Sprinkler` / `CK_Composter` / `CK_Fertilizer` | `ck_agriculture_*` |
| 蓝图 | `blueprint` | `[ColonyKit][Blueprint]` | 无固定建筑名 | `ck_blueprint_*` |
| 机器人 | `robotics` | `[ColonyKit][Robotics]` | `CK_ChargingPod` / `CK_Robot*` | `ck_robotics_*` |
| 本地化 | `l10n` | `[ColonyKit][L10n]` | 无 | `ck_l10n_*` |

全局约定：

- 所有自定义 `defName` 带 `CK_` 前缀；发布后不改名（存档契约）。
- 所有 `Scribe` key 以 `ck_<module>_` 开头；只增不改名。
- Harmony 补丁类名 `Patch_<Target>_<Module>`；Harmony Id 固定 `local.colonykit`。

## 4. 功能调查矩阵

| 功能 | 日志 tag | 首要文件 | 最常见的三种症状 |
|---|---|---|---|
| 框架内核 | `[Core]` | `Source/Core/Modules/ModuleRegistry.cs` | 模块没初始化 / 某模块拖垮其他模块 / 日志无前缀 |
| 设置系统 | `[Core]` | `Source/Core/SettingsUI.cs` | 设置页没有分节 / 开关无效 / 设置不落盘 |
| 水网 | `[Water]` | `Source/Core/Water/WaterNet.cs` | 消费者一直停机 / 存量不恢复 / 读档后管网断 |
| 淋浴 | `[Hygiene]` | `JobDriver_TakeShower.cs` | 需求不出现 / 洗澡 Job 卡住 / 断水不提示 |
| 立体库 | `[Storage]` | `CompWarehouse.cs` | 物品消失 / 原版账单看不到 / 出库不生成 |
| 农业 | `[Agriculture]` | `MapComponent_FertilityGrid.cs` | 肥力不生效 / 喷灌不停机 / overlay 不刷新 |
| 蓝图 | `[Blueprint]` | `BlueprintLibrary.cs` | 捕获为空 / 放置缺建筑 / 缺 Def 红字 |
| 机器人 | `[Robotics]` | `Need_RobotEnergy.cs` | 不自动充电 / 0% 不恢复 / 休眠不算睡眠 |
| 本地化 | `[L10n]` | `Languages/*/Keyed/` | 界面 `Keyed.xxx` / 缺简中 / 繁中缺键 |
| 构建发布 | 无运行时 | `build.ps1` / `verify.ps1` | 编译红 / zip 缺文件 / 部署后旧 DLL |

## 5. 症状 → 检查顺序

| 症状 | 先查 | 再查 |
|---|---|---|
| Mod 列表里没有 ColonyKit | `About/About.xml`、`packageId`、`supportedVersions` | `About/` 是否在第一层、文件夹是否多套一层 |
| 有 Mod 但完全没有内容 | `Assemblies/ColonyKit.dll`、`Defs` 根元素、`defName` | 程序集依赖是否齐全（缺依赖会被整包丢弃） |
| 设置页没有模块分节 | `ModuleRegistry` 是否注册、`ICKModuleSettings` 是否实现 | `SettingsUI.Draw` 是否遍历模块 |
| 模块开关无效 | `ModuleRegistry.IsEnabled` 的读取点 | Harmony/Gizmo/JobGiver 是否都判了开关 |
| 淋浴一直停机 | 水网存量、断电、预约、`Need_Hygiene` 注入 | `docs/decisions/hygiene.md` 的 DBH 共存结论 |
| 仓库物品「消失」 | `ThingOwner` 内容、拆除掉落、存档节点 | `docs/decisions/storage-kernel.md` 的账单限制 |
| 肥力不生效 | `CalculateFertilityAt` Postfix 是否命中 | 是否因 DBH 软停用、脏格是否刷新 |
| 蓝图放置缺建筑 | 记录里的 `defName` 是否还存在 | schema 版本、缺 Def 警告清单 |
| 机器人不充电 | 电量阈值、充电桩预约、电力 | `IsSleeping` Patch、draft 状态 |
| 界面出现 `Keyed.xxx` | 对应语言 `Keyed` 文件、key 拼写 | `check-l10n.ps1`（M7-5） |
| 存档红字 / 丢数据 | `Scribe` key 是否改名、Def 是否改名 | 旧存档的 `ck_*` 节点 |
| 性能尖峰 | 是否有每 tick 全图扫描 | 水网/肥力是否按 250 tick 批量、仓库是否遍历库存 |
| Harmony 启动红字 | 目标方法签名、`PatchAll` 所在程序集 | 模块开关是否让补丁提前 return |

## 7. 决策记录

所有「为什么选 A 不选 B」写进 `docs/decisions/`，不要只留在聊天记录或提交说明里。参见 [decisions/Index.md](decisions/Index.md) 的模板与待定列表。

## 8. 文档纪律

- [README 任务清单](../README.md#5-任务清单) 是**唯一进度源**；文档状态必须与它一致。
- 任何已标 ✅ 的功能，必须能在代码里找到对应文件；找不到就降级为 🧩/📄。
- 修 bug 时同一次提交更新：任务清单、功能文档「完成情况」、README 变更记录。
- 稳定标识（模块 Id、日志 tag、`defName`、`Scribe` key、Harmony Id）一旦发布不改；必须改时在决策记录里写迁移方案。
- 不要用「大概是」「可能是」写结论；写「查了什么、看到什么、结论是什么」。
