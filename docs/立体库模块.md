## 简介

立体库是一栋 3×3 的电力建筑：小人把货送到「入库口」，物品被吸入库内（不占地图格），库面板里可以筛选、排序、按数量取出。容量按堆计，默认 24，可在设置页调整。

本模块风险最高的是**存储内核选型**：`ThingOwner` 里的物品不在地图 `ListerThings` 中，原版账单/搬运/搜索可能看不见。M3-0 必须先做 A/B/C 原型再定。

## 描述

- `CK_VerticalWarehouse`（3×3，耗电）+ `CompWarehouse`：内部 `ThingOwner`，容量默认 24 堆（设置页 1–200），过滤/优先级/禁用清单。
- 入库：`WorkGiver_HaulToWarehouse` 找活，`JobDriver_StoreInWarehouse` 把物品送到入库口，成功后 `ThingOwner.TryAdd`。
- 出库：库面板「取出」→ `JobDriver_WithdrawFromWarehouse` 把物品放到出库口或目标库存区，支持整堆/按数量。
- UI：`ITab_ContentsWarehouse` 显示库存、过滤、优先级、填充度；Gizmo 提供清空/禁止入库/升级。
- 容量：默认 24 堆，设置页可调；T1/T2/T3 研究提升堆叠倍率。
- 存档：`ThingOwner` + 建筑状态（过滤/优先级/禁用/升级），读档保持内容。
- 兼容：Stack XXL 下堆叠上限变化；LWM Deep Storage 类 Mod 检测并提示；拆除建筑时物品掉落到出库口。

### 存储内核三选一（M3-0）

| 方案 | 做法 | 代价 |
|---|---|---|
| A | `ThingOwner` + 自定义入库/出库 Job + 自定义取货请求 | 原版账单看不见库存，需要出库接口 |
| B | 继承 `Building_Storage` + 自定义 `SlotGroup`，每格多堆 | 要改堆叠/搬运，和 Stack XXL 交互复杂 |
| C | A + 定向 Harmony（`ListerThings` / `GenClosest`）让原版能搜到 | 侵入性最强，兼容性最好 |

## 绘制调用逻辑图

```text
搬运需求 (Haul)
      │ WorkGiver_HaulToWarehouse
      ▼
JobDriver_StoreInWarehouse
      ├─ 预约入库口
      ├─ 携带物品到场
      └─ CompWarehouse.TryAdd(thing)
             ├─ 过滤/禁用/容量检查
             └─ 成功：物品离开地图 → ThingOwner

出库（玩家在 ITab 点“取出”）
      ▼
JobDriver_WithdrawFromWarehouse
      ├─ CompWarehouse.TryWithdraw(def, count)
      ├─ 在出库口生成物品
      └─ 小人搬到目标库存区 / 交给玩家指定

每 250 tick（可选）:
  CompWarehouse.TickRare() → 腐烂/温控/电力状态（不做每 tick 库存遍历）
```
